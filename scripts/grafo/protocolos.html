Las dos capas

Llamadas (sólidas): extraídas del índice. Sólo existen dentro de cada binario — un .c del PSoC no puede llamar a un .js del navegador.

Protocolos (punteadas): los enlaces PSoC↔ESP↔web que ningún grafo de llamadas puede ver, porque cruzan procesos y medios físicos. Derivados leyendo el código, no inferidos:

UART + SYNCpsoc_uart.cpp
ESP-NOWespnow_transport.h
WebSocket /wsweb_relay.h
HTTP /enlace/*web_server.h
Transporte MATLABmatlab_transport.h

sync_protocol.h existe idéntico en los dos firmwares (maestro y esclavo): es el contrato de sincronización versionado por duplicado, no compartido por include.

Lectura del grafo

Tamaño del nodo = llamadas internas del archivo. Grosor de arista = llamadas medidas entre archivos.

Núcleo oculto: geophone_scope/field_review_data.py — 11 módulos del servidor HTTP dependen de él (alignment 24, averages 16, filters 12, grouping 6, captures 5, overlays 5, signal_view 5, catalog 3, picks 3, dataset 3, datacache 1). El servidor web depende de un módulo que vive del lado del scope PyQt.

calculos_modelados es un archipiélago: 21 scripts, casi ningún vínculo entre ellos y ninguno con el resto del repo (fan-in 0, fan-out 0). Se comunican por archivos en data/, no por código. Las únicas dos aristas internas son analizar_sweeps → cancelar_armonicos y Subsystem.c → rt_nonfinite.c (código generado por Simulink).

MATLAB de interfaz (src/interfaces/matlab) son dos copias del mismo marcar_secuencia.m, una por banco de pruebas.

Qué quedó afuera

Generated_Source/PSoC5: código de PSoC Creator. Domina el grafo crudo (main.c le hace 40 llamadas a CyBootAsmGnu.s, 20 a cada Timer_*.c) pero no es diseño propio.

Falsos positivos entre lenguajes: el resolvedor cruza símbolos homónimos (main, setup) y genera aristas imposibles — calibration.c → fix_dispersion_layer.py, slave/main.cpp → masw_adsurf.py, masw_analysis.py → enlace.js. Descartadas.
